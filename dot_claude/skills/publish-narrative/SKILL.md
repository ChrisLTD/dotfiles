# Publish Narrative

Copies the narrative HTML generated by `/pr-narrative-review` into a dedicated private GitHub Pages repo, regenerates the index, commits, pushes, and returns the live URL.

## Step 1: Check config

Read `~/.config/ai-artifacts/repo-path`. If the file is missing or empty, run the setup flow below before continuing.

### Setup flow (first run only)

Walk the user through this once:

1. **Create the repo:**
   ```bash
   gh repo create ai-artifacts --private --description "AI-generated artifacts (narrative reviews, etc.)"
   ```
2. **Clone it** to a local path of the user's choice (default `~/ai-artifacts`):
   ```bash
   git clone git@github.com:<username>/ai-artifacts.git ~/ai-artifacts
   ```
3. **Enable GitHub Pages** — the GitHub API does not reliably enable Pages for empty repos, so ask the user to do this manually: repo Settings → Pages → Source: Deploy from branch → `main` → `/ (root)` → Save.
4. **Save the path:**
   ```bash
   mkdir -p ~/.config/ai-artifacts
   echo "$HOME/ai-artifacts" > ~/.config/ai-artifacts/repo-path
   ```

After setup, continue to Step 2.

## Step 2: Find the narrative HTML

- `ARTIFACTS_REPO=$(cat ~/.config/ai-artifacts/repo-path | tr -d '[:space:]')`
- If a PR number was passed as args, look for `.scratch/pr-<number>-narrative.html` in the current working directory.
- Otherwise, find the most recently modified file matching `.scratch/*-narrative.html`:
  ```bash
  ls -t .scratch/*-narrative.html 2>/dev/null | head -1
  ```
- If no HTML is found, tell the user to run `/pr-narrative-review` first.

## Step 3: Identify the source repo name

Derive it from the git remote, falling back to the directory name:

```bash
git remote get-url origin 2>/dev/null | sed 's/.*[:/]\([^/]*\)\.git$/\1/' || basename "$(git rev-parse --show-toplevel 2>/dev/null || pwd)"
```

## Step 4: Copy the HTML into the artifacts repo

```bash
SOURCE_REPO=<derived above>
HTML_FILE=<filename, e.g. pr-42-narrative.html>
DEST_DIR="$ARTIFACTS_REPO/$SOURCE_REPO"

mkdir -p "$DEST_DIR"
cp .scratch/$HTML_FILE "$DEST_DIR/$HTML_FILE"
```

## Step 5: Regenerate index.html

Scan all `*.html` files in the artifacts repo (excluding `index.html` itself), group by subdirectory, and write a fresh `$ARTIFACTS_REPO/index.html`. Use this structure:

```html
<!DOCTYPE html>
<html lang="en">
<head>
<meta charset="utf-8">
<title>AI Artifacts</title>
<style>
  body { font-family: system-ui, sans-serif; max-width: 640px; margin: 2rem auto; padding: 0 1rem; color: #1a1a1a; }
  h1 { font-size: 1.25rem; margin-bottom: 1.5rem; }
  h2 { font-size: 1rem; margin: 1.25rem 0 0.5rem; color: #555; }
  ul { list-style: none; padding: 0; margin: 0; }
  li { padding: 0.25rem 0; }
  a { color: #0066cc; text-decoration: none; }
  a:hover { text-decoration: underline; }
</style>
</head>
<body>
<h1>AI Artifacts</h1>
<!-- one <h2> per source repo subdirectory, one <li><a> per HTML file -->
</body>
</html>
```

List files in reverse-chronological order within each group (newest first). Use the filename as the link text (strip the `.html` suffix). Generate this file in full — do not append to an existing one.

## Step 6: Commit and push

```bash
git -C "$ARTIFACTS_REPO" add .
git -C "$ARTIFACTS_REPO" commit -m "Add $SOURCE_REPO/$HTML_FILE"
git -C "$ARTIFACTS_REPO" push
```

## Step 7: Output the URL

Derive the GitHub Pages URL from the remote:

```bash
git -C "$ARTIFACTS_REPO" remote get-url origin
# https://github.com/<user>/<repo>.git  or  git@github.com:<user>/<repo>.git
```

Parse out `<user>` and `<repo>`, then build:

```
https://<user>.github.io/<repo>/<source-repo>/<filename>.html
```

Print this URL to the user. Note: GitHub Pages can take up to a minute to deploy on the first push; subsequent pushes are usually live within seconds.
